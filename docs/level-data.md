# Level Data & Goldens

## Sources

Three level formats feed the same `LevelData` shape
(`src/logic/game-types.ts`):

| Source | Files | Parser | Purpose |
|--------|-------|--------|---------|
| Official campaign | `src/levels-data/00-official.ts` … `11-official.ts` (12 packs, ~566 levels), aggregated by `src/levels.ts` | `parse-level.ts` | The shipped game — generated by `pnpm import-levels:official`, do not hand-edit |
| Text fixtures | `levels/**/*.txt` | `parse-level.ts` | Hand-written/ported boards for tests and golden replays; supports multiple entities per cell |
| ASCII fixtures | test-inline / tool-driven | `parse-ascii-level.ts` | Map-art fixtures with palette metadata (`LevelMeta`) |

## Text Fixture Format (`parse-level.ts`)

Semicolon-separated statements:

```text
Title Baba Is You; Size 33x18; Wall 0,0 1,0 …; Baba 11,10; FLAG 5,5; Win 5,6
```

- `Title`, `Size <w>x<h>` headers; `background` lines are ignored
- Entity statement: `<Name> <x>,<y> …` — one name, many cells
- Case flags text: `Baba` is the noun card, `baba` the object; names
  without case (`3d`, digits) take a `!` suffix (`3d!`)
- `Name@<dir>` pins an initial facing (`belt@right`)

## ASCII Fixture Format (`parse-ascii-level.ts`)

Ported from the predecessor Rust project's fixtures: `key = value` metadata
and single-char legend entries, `---` separated map layers merged
cell-wise. `o = "win" on water` stacks bottom-to-top; uppercase glyphs
produce the text entity of the legend noun; `palette`/`background`/
`+ glyphs = cx,cy` color overrides resolve into `LevelData.meta`.

## Official Import Chain

`pnpm import-levels:official` (`src/tools/import-official-levels.ts`) reads
the local `data/baba` dump (gitignored — the extracted `Baba Is You/Data/`
folder, ground truth `rules.lua`/`letterunits.lua`/`blocks.lua` included)
and regenerates `src/levels-data/*.ts` + `src/levels.ts`:

```text
*.ld → import-official-levels-parse.ts      [general]/[tiles]/[levels]/… sections
*.l  → import-official-levels-binary.ts     binary layer grids
object slots → -object-table.ts             canonical tileslist from values.lua
             → -tile-map.ts                 per-level slot resolution:
                                             [tiles] override → tileslist → currobjlist
             → -global-reference.ts         cross-level tile disambiguation
convert → -convert.ts                       → entity-list text + filter report
verify  → -verify.ts                        `pnpm verify-levels:official`
```

- `leveltype=1` files are overworld maps — parsed for verification but
  never converted into playable data (the app uses a flat menu).
- Import filters drop unplayable conversions (no `you`/`win` text, too many
  facing-text tiles, unknown cards, name-index collisions) and report them.
- `build-level-code-map.ts` regenerates `src/tools/level-code-map.json`:
  community solutions name levels by in-game code (`Level Lake-3`,
  `Chasm-Extra 1`), which the official engine derives from the hub map's
  `mapid` + entry style — the map lets importers resolve those names to
  campaign indices.
- Sibling importer `src/tools/import-official-sprites.ts` extracts the
  official `Data/Sprites/{name}_0_*.png` art into
  `src/web/pixel-sprites/data/objects-official.ts` (generated — promote a
  sprite by hand-drawing it under the same name in the authored data
  files, see [docs/rendering-3d.md](./rendering-3d.md)).

## Goldens

`goldens/**/*.json` — recorded winning playthroughs. Format:

```json
{
  "level": "levels/…",           // fixture path, or "" when levelIndex/levelData pins it
  "levelIndex": 0,               // campaign index (solver-emitted records)
  "levelData": { … },            // embedded layout — the board it was recorded on
  "inputs": "rrddlluuw…",        // u/d/l/r/w/z codec (replay-input.ts)
  "initial": "…", "hashes": ["…"], "final": "…", "status": "win"
}
```

- `src/logic/replay.ts` replays the input string through `step()`;
  `serializeState`/`hashState` (sha256-16) pin every step's outcome.
  `compressInputs` folds `z` detours into the effective path.
- `src/logic/goldens.test.ts` replays every file and enforces consistency:
  `levelIndex` records must match the campaign level's layout signature;
  `levelData` + `level` records must match the fixture file. Known blind
  spot: the signature ignores `dir`, so facing-only drift passes.
- Producers: `scripts/port-rust-goldens.ts` (predecessor recordings),
  `src/tools/solve-levels.ts --emit-goldens/--resolve-goldens/
  --improve-goldens` (search + waypoint re-solve),
  `src/tools/import-solutions.ts` (community archives, replay-verified
  through our own engine), `scripts/resnapshot-goldens.ts`,
  `scripts/diff-rust-golden.ts`. Sweep status lives in
  [docs/solver-handoff.md](./solver-handoff.md).
- App side: `scripts/build-single-html.ts` runs `app-golden-binding.ts`
  at build time to pin each record to a campaign level (explicit
  `levelIndex` > unique normalized title > unique layout signature;
  ambiguous stays unbound), emits the `baba-golden-index` module
  (`levelIndex → name`) plus a `goldens.json` lazy payload of bound
  records only (embedded layouts identical to the campaign parse are
  stripped); the game HUD's **Solution** button plays the bound recording
  via `app-replay.ts` — see
  [docs/web-architecture.md](./web-architecture.md).

## Conventions

- `data/` and `tools-out/` are gitignored local scratch — the official dump
  and sweep/debug scripts live there and are never committed.
- `levels-data/*.ts` is generated; fix levels at the importer, not the pack.
- Golden `inputs` never contain `z` from the solver — undos only appear in
  hand/community recordings.
